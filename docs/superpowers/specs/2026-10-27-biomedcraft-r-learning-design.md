# BiomedCraft：生物医学 R 语言任务岛学习仓库设计

- 日期：2026-10-27
- 状态：设计已确认，待用户复核
- 学习者：大一生物医学专业学生，R 零基础，统计基础较弱
- 目标仓库：私有学习库 `biomed-quest` + 公开作品集 `biomed-portfolio`

## 1. 背景与目标

用户希望通过“做项目”学习 R 语言和生物医学知识，并把学习过程、教程、代码记录到 GitHub，方便复习和分享。用户对基因分析感兴趣，喜欢 Minecraft，希望在不过度增加维护成本的前提下获得游戏化的学习体验。

本设计要解决的问题不是“如何学完 R 语法”，而是：

1. 让一个 R 零基础、统计基础较弱的大一学生，在 16 周内建立可持续的学习节奏。
2. 用一条真实的基因分析主线，把零散知识串成可复现的项目。
3. 在 AI 可以随时生成代码的时代，训练“定义问题、验证结果、解释代码”的能力，而不是复制代码。
4. 让学习过程本身成为可复习、可展示的资产。

## 2. 学习者画像与约束

| 项目 | 现状 | 设计含义 |
|---|---|---|
| 专业 | 生物医学，大一 | 生物概念可快速补，统计和编程需要脚手架 |
| R 基础 | 零基础 | 第 1 关必须覆盖安装、对象、数据框、第一次提交 |
| 统计基础 | 听过均值、标准差、p 值，但说不清 | 不先讲公式，用模拟、图形和“统计补给箱”建立直觉 |
| Git/GitHub | 有账号，未真正提交过 | 第 1 关手把手完成第一次 commit；每周固定提交 |
| 时间 | 每周 4–6 小时 | 每关设计为“核心 3 小时 + 可选 2 小时”，允许缓冲 |
| 设备 | macOS + Linux | 安装指南覆盖两条路径；路径处理统一用 `here()` |
| 兴趣 | 基因分析、Minecraft、手机摄像头测心率 | 主线做基因分析；Minecraft 做叙事和成就；心率做可选支线 |
| 公开意愿 | 学习过程私有，完成项目公开 | 双仓库：私有学习库 + 公开作品集 |
| AI 使用 | 希望 AI 当严格教练，延迟给答案 | 三级提示、30 分钟规则、AI 日志、最终关禁 AI 写代码 |

## 3. 非目标

- 不做真正可玩的 Minecraft 模组或游戏引擎。
- 不覆盖湿实验、临床诊断或任何医疗建议。
- 不追求 R 语言全栈（不包含 Shiny、包开发、C++、深度学习框架）。
- 不在第一季做单细胞、空间转录组或机器学习。
- 不把 16 周内容一次性全部写完；按周解锁，按反馈调整。
- 不公开个人数据、账号信息或未脱敏的心率原始数据。

## 4. 成功标准

第一季结束时，用户应能：

1. 在一个**没见过的基因表达数据集**上独立完成：读入与检查、清洗、QC、差异表达、富集分析、可视化、结果解释。
2. 用 Quarto 产出可复现报告，包含 `sessionInfo()`、数据来源、方法说明和局限性。
3. 用 5 句话向非专业听众解释“这张图说明什么、为什么、有什么不确定”。
4. 在 AI 只做审查、不写代码的条件下完成最终 Boss。
5. 拥有一个结构清晰、可持续更新的私有学习库，以及至少一个公开作品集项目。

可量化的验收：

- 16 周内完成 12 个关卡、2 个小 Boss、Boss 1 与最终 Boss；Boss 2 为加分项。
- 每周至少 2 次有意义的 commit，至少 1 篇复盘。
- 13 枚成就中至少解锁 10 枚。
- 公开作品集至少 1 个完整项目，README 中英双语可读。

## 5. 设计原则

1. **先看见终点，再走新手村**：W0 先跑通一个打包好的迷你分析，知道学完能做什么。
2. **项目驱动，但基础不跳步**：每关都有明确产出，同时保留必要的基本功练习。
3. **游戏化服务于学习行为**：只保留成就、地图、视觉三类低成本元素；不做交易、饥饿值、生命值等重规则。
4. **AI 延迟介入**：先自己想、自己写、自己调试；AI 只在卡住时给提示，交付后做审查。
5. **可复现优先于好看**：能从头跑通、能解释每一步，比图漂亮更重要。
6. **可持续优先于完整**：每关核心 3 小时，宁可不做支线，也不要断更。
7. **公开的是作品，不是草稿**：学习过程留在私有库，公开库只放打磨后的项目。

### 缓冲策略

- W13–14 同时作为缓冲。若进度落后，优先保证 Boss 1；Boss 2 降级为可选支线，最终 Boss 改为在 Boss 1 数据上做“新问题”分析。
- 每关标记“核心任务”和“可选支线”。核心任务必须完成；支线不影响通关，不加 XP，只记录完成度。
- 连续两周未完成关卡时，暂停解锁新内容，先用一周做“经验修补”。

## 7. 关卡详细设计

### L1 新手村：第一次进入世界

- 学习目标：安装 R、RStudio/Positron、Quarto、Git；理解对象、向量、数据类型；完成第一次 commit。
- 任务卡：创建 `hello.R`，打印玩家名、当前周、学习目标；创建 `hello.qmd` 并渲染。
- 自检：`check_level_01.R` 检查文件存在、脚本可运行、Quarto 输出存在。
- 复盘三问：哪一步最卡？报错说明了什么？下次如何更快？
- 成就：木镐（第一次跑通 R 脚本）。

### L2 合成台：把材料组合成函数

- 学习目标：数据框、因子、列表、函数、条件分支、`apply` 家族。
- 情境：Minecraft 合成表（木板、木棍、工作台）作为数据框；写一个 `craft()` 函数判断材料是否足够。
- 交付：`crafting.R` + 3 个测试用例。
- 成就：第一次合成（第一个 `dplyr`/函数管道）。

### L3 工作台：清洗真实表格

- 学习目标：`readr`、`dplyr` 五动词、缺失值、`janitor`、连接。
- 数据：`survival::lung`（肺癌临床数据）+ 合成 Minecraft 玩家数据。
- 交付：清洗后的 CSV、数据字典（每列含义、单位、缺失情况）、3 条数据质量问题。
- 成就：工作台（完成第一个可复现清洗流程）。

### L4 地图：把数据画成图

- 学习目标：`ggplot2` 的映射、几何对象、分面、标度、图注、配色。
- 交付：4 张图（分布、分组比较、趋势、关系），每张图配 2 句图注。
- 成就：地图绘制者（第一张完整 `ggplot`）。

### 小 Boss 1：一页数据故事

- 目标：用 L1–L4 的技能，把一份 CSV 变成一页 Quarto 报告。
- 数据：Minecraft 玩家行为数据，或用户已有的心率 CSV（二选一）。
- 交付：`report.qmd` + 3 张图 + 200 字结论。
- 评估：能运行、图有图注、结论不超出数据。

### L5 附魔台：统计直觉

- 学习目标：均值/中位数/标准差、分布、抽样、中心极限定理、p 值直觉、置信区间直觉。
- 方法：先模拟，再画图，最后才给定义；不要求推导公式。
- 交付：统计小抄（每概念一句话 + 一张图）+ 一个模拟实验（如“重复抽样 1000 次”）。
- 统计补给箱：偏态数据为什么不能用均值？p 值不是“结论为真的概率”。
- 成就：附魔台（能解释一个统计概念）。

### L6 红石电路：函数、迭代与调试

- 学习目标：函数参数与返回值、`purrr::map`、`broom::tidy`、`reprex`、常见报错。
- 交付：3 个可复用函数 + 错误日志（报错原文、原因、修复）。
- 成就：红石工程师（写出第一个可复用函数）。

### L7 下界要塞：基因数据是什么

- 学习目标：中心法则、FASTQ/BAM/count matrix 的区别、实验设计、批次效应、基因 ID 与注释。
- 交付：一张概念图 + `airway` 数据字典（样本、分组、协变量）。
- 成就：下界通行证（能说清 count matrix 是什么）。

### L8 烈焰棒：QC 与标准化

- 学习目标：`airway` 数据结构、`DESeq2::vst`、PCA、样本相关性、异常样本判断。
- 交付：QC 报告（PCA、箱线图、样本距离热图）+ “这批数据可信吗”的判断。
- 成就：QC 守门人（发现或排除一个数据质量问题）。

### 小 Boss 2：数据质量审查

- 目标：给出一份 5 项 QC 清单，并解释每项不通过时该怎么办。
- 交付：`qc_checklist.md` + 一次同伴/自我复核记录。

### L9 末地城：差异表达

- 学习目标：`DESeq2` 模型、design formula、normalization、shrinkage、FDR、火山图。
- 交付：差异表达表（含 `log2FoldChange`、`padj`）、火山图、3 个候选基因及理由。
- 成就：末地行者（完成一次差异表达分析）。

### L10 末地船：富集与解释

- 学习目标：GO/KEGG、ORA 与 GSEA 的区别、背景基因、FDR、结果解释的边界。
- 交付：富集图 + 3 段解释（每条包含“结果、可能的生物学含义、不能说明什么”）。
- 成就：村庄英雄（把结果讲给非专业听众）。

### L11 返回传送门：热图与叙事

- 学习目标：`ComplexHeatmap`、样本/基因聚类、注释条、结果叙事、Quarto 报告结构。
- 交付：可复现报告（问题、数据、方法、结果、局限性）。
- 成就：经验修补（根据审查意见改一版）。

### L12 龙蛋：独立分析

- 目标：在教师提供的新数据集上，限时 3 小时完成最小完整分析。
- 规则：不允许 AI 写代码，只能查文档；允许使用自己的函数库。
- 交付：`analysis.qmd` + 5 句话解释 + 一页“我还不确定什么”。
- 评估：正确性、可复现性、解释质量、独立性。

### Boss 1：airway 全流程

- 范围：从原始 count 到 QC、DE、富集、热图、报告。
- 时间：2 周。
- 交付：`projects/01-airway-rnaseq/`，含英文 README、中文说明、`analysis.qmd`、图、`sessionInfo.txt`。
- 这是第一个公开作品集候选项目。

### Boss 2：TCGA-LUAD 肿瘤 vs 正常

- 数据：`recount3` 的 TCGA-LUAD 子集，预过滤到 40–60 个样本、表达量较高的基因；若下载不稳定，使用课程内置的预处理 count matrix。
- 学习重点：肿瘤/正常分组、批次与临床混杂、样本纳入标准、结果不能直接当临床结论。
- 时间：1 周（可作为可选支线）。
- 交付：`projects/02-tcga-luad/`，必须包含“混杂因素与局限性”一节。

### 最终 Boss：新数据 + 公开作品集

- 数据：`pasilla`（Bioconductor）——课程中未出现过的小型 RNA-seq 数据集。
- 规则：AI 不写代码；完成后 AI 只做审查。
- 交付：公开 `biomed-portfolio` 中的项目页 + 5 分钟自讲录屏 + 复盘。
- 通过条件：评估量表 ≥ 6/8，且正确性、解释两项不得为 0。
- 成就：传说的起点（公开发布第一个作品集）。

### 可选支线：心率数据分析

- 定位：不进入主线，不影响通关；用用户已有的 RGB/心率 CSV 复现“信号清洗 → 滤波 → 峰值检测 → 心率计算 → 可视化”。
- 工具：`readr`、`ggplot2`、`pracma` 或 `signal`；不开发手机 App，不做实时采集。
- 交付：`side-quests/heart-rate/` 下的一页报告 + 5 句话解释。
- 数据：原始数据只留本地；公开版本使用合成或脱敏 CSV。

## 8. 每周学习循环

| 时间 | 动作 | 产出 |
|---|---|---|
| 15 min | 读任务卡，确认本周成就目标 | 一句话目标 |
| 45 min | 概念补给 + 跟着做热身 | 热身代码 |
| 2.5 h | 主任务，自己写；卡住先记问题 | 关卡代码/报告 |
| 30 min | 运行自检脚本，修正 | 通过记录 |
| 40 min | 复盘三问 + 英文 TL;DR | `journal/wXX.md` |
| 15 min | commit、更新 `PROGRESS.md`、点亮地图 | 成就证据 |
| 20 min（可选） | 提交后 AI 代码审查 | 审查记录 |

每周至少 2 次 commit：一次是主任务，一次是复盘/成就。忙碌周只完成“核心 3 小时”，支线顺延。

## 10. README 与视觉规范

README 是“存档手册”，不是普通项目说明。首屏必须让读者在 10 秒内知道：这是谁、在学什么、进度到哪、怎么开始。

### 10.1 README 结构

> 一个生物医学大一学生的 R 语言生存存档

🟩 当前境界：Lv.0 迷路的村民
❤️ 模式：生存（严格教练，延迟给答案）
🌍 世界种子：airway-v1
📦 进度：0/12 关卡 · 0/3 Boss
🏆 成就：0/13

主世界   新手村 → 合成台 → 工作台 → 地图
            ↓ 传送门

            ↓ 传送门

### 11.2 XP 与等级

- XP 只来自单元通关：12 个关卡 × 100 + 2 个小 Boss × 150 + 3 个 Boss × 400 = 2700 XP。
- 成就只发徽章，不额外加 XP，避免“刷成就”替代学习。
- 等级阈值：Lv0 0、Lv1 400、Lv2 900、Lv3 1500、Lv4 2100、Lv5 2700。
- 等级名称：迷路的村民 → 石匠 → 红石学徒 → 炼金术士 → 末地行者 → 生物医学数据分析师。
- Lv5 为全收集等级，需要完成加分项 Boss 2；跳过 Boss 2 时最高为 Lv4（2300 XP）。
- XP 只用于展示进度，不兑换提示、不惩罚失败。

### 11.3 地图与传送门

- `MAP.md` 用 Mermaid 维护关卡状态：🔒 未解锁、⚔️ 进行中、✅ 已通关、🐉 Boss。
- GitHub Projects 四列：Locked、In Progress、Cleared、Boss。
- commit 规范：`L03: clean clinical data`；成就单独提交 `PROGRESS: claim A03`。
- 每周 tag：`w01`、`w02`；每幕 tag：`act-1`、`act-2`、`act-3`。
- “传送门”是幕切换仪式：完成一幕的全部关卡后，写一页“幕总结”，再解锁下一幕。

## 12. AI 严格教练协议

### 12.1 三阶段

1. **写之前**：AI 只澄清任务、追问理解，不给代码。
2. **卡住时**：三级提示。
   - 一级：概念提示（“先检查分组变量是不是因子”）。
   - 二级：函数/包提示（“看看 `dplyr::count()`”）。
   - 三级：伪代码（不含完整可运行代码）。
   - 超过 30 分钟仍未解决，才可给最小可运行示例；必须记入 `journal/ai-log.md`。
3. **提交后**：AI 只做审查，不重写。审查维度：正确性、可复现性、统计解释、代码可读性。

### 12.2 强制记录

`journal/ai-log.md` 每次记录：

- 我的问题（原话）
- AI 给的提示级别
- 我采用了什么、拒绝了什么
- 下次遇到类似问题，我先查什么

### 12.3 解释关

每关结束前，必须写 5 句话：

1. 这关解决了什么问题？
2. 输入是什么、输出是什么？
3. 关键函数/方法为什么选它？
4. 结果说明什么？
5. 还有什么不确定？

AI 可以追问，直到这 5 句没有含糊词（如“大概”“可能”没有具体对象）。

### 12.4 最终 Boss 禁令

- 不允许 AI 生成代码、调试代码或代写报告。
- 允许查官方文档、包 vignette、教科书。
- 交付后 AI 只做审查和提问。
- 若发现 AI 代写，项目退回重做；这是唯一的“惩罚”规则。

## 13. 内容标准与双语规范

### 13.1 每关内容清单

- 任务卡：目标、背景、步骤、通关条件、预计时间。
- 概念讲解：中文正文，开头 5 条英文 TL;DR；关键术语中英并列。
- 热身：可运行的小例子，5–15 分钟。
- 主任务：带 TODO 的起点代码，不包含完整答案。
- 自检：`check_level_XX.R`，失败时给下一步提示，不直接给答案。
- 复盘模板：三问 + 5 句话解释 + AI 日志链接。
- 成就：条件、证据、XP。
- 参考解：通关后解锁，放入 `solutions/`。

### 13.2 双语规范

- 教程正文中文；开头英文 TL;DR（5 条以内）；代码注释英文；变量名英文。
- 图表标题、坐标轴、图例英文；图注中英各一句。
- 公开作品集 README 英文为主，附中文摘要。
- 不追求逐段对照，优先保证学习节奏。

### 13.3 代码规范

- 使用 tidyverse 风格；`snake_case` 命名；每行不超过 100 字符。
- 路径统一用 `here::here()`；不写绝对路径。
- 每个脚本开头写目的、输入、输出、作者、日期。
- 关键步骤有英文注释；不注释显而易见的代码。
- 提交前运行 `styler`（可选）和自检脚本。

## 15. 评估与证据

### 15.1 关卡通关

必须同时满足：

- `check_level_XX.R` 全部通过。
- 复盘三问完成。
- 5 句话解释完成。
- 至少 1 次 commit，信息符合规范。
- 成就领取附证据链接。

### 15.2 Boss 评估量表

| 维度 | 0 分 | 1 分 | 2 分 |
|---|---|---|---|
| 正确性 | 跑不通或结果错误 | 能跑通，有小错误 | 结果正确，边界情况有说明 |
| 可复现性 | 依赖手动步骤 | 基本可复现，缺版本信息 | `renv` + `sessionInfo()` + 一键渲染 |
| 解释 | 只贴图 | 能描述结果 | 能说明含义、局限和不确定性 |
| 独立性 | 明显 AI 代写 | 有 AI 参与但能解释 | 独立完成，AI 只审查 |

通过：总分 ≥ 6/8，且正确性、解释不得为 0。

### 15.3 间隔复习

- 每 4 周一次“经验修补”：回访旧关卡，改一处代码或补一段解释。
- 成就 A12 需要提交 diff 和复盘。
- 复习优先看自己的旧代码和 AI 日志，不重看教程。

## 16. 风险与对策

| 风险 | 表现 | 对策 |
|---|---|---|
| 游戏化过重 | 花更多时间做徽章，不写代码 | 视觉每周上限 30 分钟；成就和地图用 Markdown/SVG，不做游戏引擎 |
| 统计挫败 | 看到 p 值、FDR 就想放弃 | 先模拟和图，再定义；每关只引入 1–2 个概念；允许“暂时不理解但会检查” |
| AI 依赖 | 代码能跑但讲不清 | 三级提示、30 分钟规则、AI 日志、5 句话解释、最终关禁 AI |
| 时间不足 | 每周 4 小时以下 | 核心/支线分层；W13–14 缓冲；落后时暂停解锁 |
| 数据下载失败 | `recount3`/Bioconductor 网络问题 | 提供预处理 count matrix；使用 `renv` 缓存；准备 Posit Cloud 备选 |
| 数据许可 | 公开了不该公开的数据 | 公开库只放脚本和衍生图；数据许可写入 README |
| 动力下降 | 连续两周断更 | 成就墙、地图点亮、公开作品集；允许“最小周”只完成 1 个 commit |
| 商标/版权 | 使用官方素材 | 自绘像素风；注明 inspired；不使用官方 Logo/材质/字体 |
